# Week 1 — Arrays and hashing

**Goal:** learn when a hash set or dictionary helps avoid repeated scans.

## Solve in this order

| # | Problem | Link | Core idea to investigate |
|---|---|---|---|
| 1 | Contains Duplicate | https://leetcode.com/problems/contains-duplicate/ | Detecting a repeated item using stored values |
| 2 | Valid Anagram | https://leetcode.com/problems/valid-anagram/ | Comparing character frequencies |
| 3 | Two Sum | https://leetcode.com/problems/two-sum/ | Tracking complements while scanning |

**Riti's instructions:**

1. Read the original problem and explain it using her own small example.
2. Try a brute-force approach first and estimate its time complexity.
3. Look for a more efficient approach, then write the code herself.
4. Test typical, empty/minimal (where valid), repeated, negative and boundary cases as appropriate to that problem.
5. Save the solution here as `contains_duplicate.py`, `valid_anagram.py`, and `two_sum.py` **only after solving**.
6. Record an explanation, complexities, time taken and a 3–7 day revision date in `progress.csv`.

## Reflection prompts

- Why might a Python set give a faster membership check than scanning a list?
- When is a dictionary more informative than a set?
- How can we justify complexity without measuring execution time?
